# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is a React Native Hacker News client built with Expo and file-based routing (expo-router). The app displays stories from Hacker News across six categories (Top, Best, New, Ask, Show, Jobs) plus past front pages by date with infinite scrolling, link previews, and a comment system.

## Package Manager

This project uses **pnpm** as its package manager (pnpm 12, specified in `package.json`; settings such as `overrides` and `allowBuilds` live in `pnpm-workspace.yaml`). Always use `pnpm` commands instead of `npm` or `yarn`.

## Architecture

### iOS Widgets (Mobile Only)

Home screen and lock screen widgets: **Stories** (`HNTopStoriesWidget`, category picker) and **Bookmarks** (`HNBookmarksWidget`). The layouts are `expo-widgets` + `@expo/ui/swift-ui` written in TSX; the only Swift is a small self-refreshing refresher that a config plugin splices into the generated Stories widget file.

1. **Files** (`apps/mobile/`):
   - `widgets/HNTopStoriesWidget.tsx` - the `'widget'` layout function plus `createWidget("HNTopStoriesWidget", ...)`; also referenced from `app.json` as `ios.initialLayout`
   - `widgets/HNBookmarksWidget.tsx` - the Bookmarks layout (medium, large); its own copy of the small helpers, since layouts cannot share code at runtime
   - `widgets/palette.ts` - the widget colour tokens, picked from `constants/colors.ts`
   - `widgets/widget-contract.json` - numbers shared by the app and the Swift (story/bookmark counts, entry spacing, stale/reload minutes, category ids)
   - `widgets/HNSelfRefreshingProvider.swift` - `HNWidgetRefresher`; not standalone, it is compiled inside the generated widget file
   - `plugins/with-widget-self-refresh.js` - config plugin (finalized mod) that patches `ios/ExpoWidgetsTarget/HNTopStoriesWidget.swift` (only that file) and appends the refresher source
   - `lib/widgets/stories.ts` - pure payload helpers (story shape, per-category merge, timeline entries; node-tested); `lib/widgets/sync.ts` - `syncTopStoriesWidget({force?})`, `syncBookmarksWidget({force?})`; `lib/widgets/tap.ts` - pure widget deep-link parsing
   - `hooks/use-widget-sync.ts` - mounted in `app/_layout.tsx` (mount + AppState `active`, both widgets)
   - `hooks/use-widget-analytics.ts` - `widget_tapped` (size, widget kind, category, story id when present) from the widget deep links
   - `ios/ExpoWidgetsTarget/` - GENERATED by the plugins on every prebuild; never hand-edit

2. **Layout rules**: the `'widget'` function is stringified and run in JavaScriptCore inside the extension. It must be self-contained: no imports/module constants (helpers like `timeAgo` live inside the function), no hooks/async. The palette is passed as props data. Only `@expo/ui/swift-ui` components the widget renderer supports work (no List/ScrollView); unknown ones render nothing. Background comes from `containerBackground(color, 'widget')` in the layout. Type-only imports (`import type`) are fine.

3. **Families**: Stories: systemSmall (1 hero story), systemMedium (3 stories), systemLarge (7 rows), accessoryRectangular (lock screen, 3 lines). Bookmarks: systemMedium (2 rows), systemLarge (7 rows) with an empty state ("Bookmark stories to see them here"). Row counts are constants at the top of the layouts.

4. **Category picker (Stories)**: a static enum parameter declared under `ios.configuration.parameters.category` of the widget in `app.json` (values = `STORY_CATEGORIES`, default `top`). expo-widgets then generates an `AppIntentConfiguration` + `AppIntentTimelineProvider` (iOS 17+) and passes the pick to the layout as `env.configuration.category`. `updateTimeline` is per widget kind, so the props carry every category: `{ stories: { top: [...], best: [...], ... }, updatedAt, palette, logoUri }` (7 lean stories each); the layout shows `props.stories[category]`. The footer/brand label names the category; Jobs hides points and comments. The plugin marks the generated configuration types `@available(iOS 17.0, *)` (the extension targets 16.4), so on iOS 16 the Stories widget is not offered (Bookmarks still is). A test pins the `app.json` values, the contract categories and the Swift endpoints to `STORY_CATEGORIES`.

5. **Data flow (Stories)**: two writers feed the same App Group timeline. The app fetches the first ids of every category (`getCategoryStoryIds`, items fetched once for all) and calls `HNTopStoriesWidget.updateTimeline()` with 24 entries spaced 30 min apart (same stories + palette; ages are recomputed from `env.date`) on app mount, foreground and Top feed pull-to-refresh (forced); non-forced syncs are throttled to 10 min. A category whose fetch failed keeps its stored stories; when nothing fresh arrived the stored timeline is never overwritten. Independently, `HNWidgetRefresher` (called from the patched `timeline(for:in:)`) refetches all categories itself when iOS asks for a timeline and the stored one is stale, so the widget stays fresh with the app closed. There is no background task in the app. The brand label shows "Updated Nh ago" after 6h. `initialProps` are redacted Top samples for the gallery / pre-sync state; a stored timeline from before the picker (`stories` as an array) is read as Top.

6. **Data flow (Bookmarks)**: local data, no self-refresh. `syncBookmarksWidget` reads `getBookmarkIds()`, fetches the 7 most recent items and writes a 24-entry timeline `{ stories, total, updatedAt, palette, logoUri }`. It is forced from the bookmark mutation `onSuccess` (`hooks/use-bookmarks.ts`) and after "Clear All", and runs throttled on mount/foreground. A sync requested while another runs triggers one more run. Offline, bookmarks keep their stored copy (points may be stale); unreadable storage never overwrites the widget.

7. **Logo**: the extension cannot read the app bundle, so `sync.ts` copies `assets/images/widget-logo.png` once into the App Group container and passes the file URI to the layouts.

8. **Config**: plugin entries in `app.json`: `expo-widgets` (App Group `group.com.danielcspaiva.hnclient`, extension bundle id `com.danielcspaiva.hnclient.HackerReaderWidgets` kept so widgets already placed survive, kinds `HNTopStoriesWidget` and `HNBookmarksWidget`) and `./plugins/with-widget-self-refresh`.

9. **Deep links**: story rows `hnclient://story/{id}`; Stories header/background `hnclient://feed/{category}` (route `app/(tabs)/feed/[category].tsx` sets the feed category and redirects to the feed); Bookmarks header/background `hnclient://bookmarks`; lock screen uses one `widgetURL`. All carry `source=widget&widgetKind=..&widgetSize=..` (plus `category=..` for Stories) for analytics.

10. **Not carried over**: `widget_added` / `has_widget_installed` analytics (no `getCurrentConfigurations` in expo-widgets).

11. **Testing**: the `ios/` dir is tracked. After changing widget plugin config run `npx expo prebuild --platform ios` (NOT `--clean`: the Podfile `post_install` carries an Xcode 27 fix bumping pod targets below iOS 15 - re-check it survives), then `cd ios && pod install`. Build, run the app once (writes the layout + timeline to the App Group), then add the widget from the Widget Gallery (long-press, Edit Widget to pick the category). Layout code edits need an app run (or rebuild for the embedded initial layout). The ExpoWidgets layout registry is regenerated by an Xcode script phase that is skipped on incremental builds; if a layout change does not show up, delete the `ExpoWidgets.build` and `Products/ExpoWidgets` outputs in DerivedData and rebuild. In dev builds a cold start from a widget tap lands on the dev launcher first, and the deep link is only delivered once connected to Metro (not an issue in release builds). `patches/expo-widgets.patch` (pnpm patch) adds an identity `React.memo` to the extension's React stub because `@expo/ui` calls it at module scope; drop it once expo-widgets ships the fix. Not available in Expo Go.

### Authentication (Mobile Only)

The mobile app supports HN authentication with a native login experience:

1. **Login Flow**:
   - Users must accept HN Guidelines on first login; the login screen (`app/auth/login.tsx`) shows `GuidelinesContent` until accepted
   - Guidelines acceptance is persisted in AsyncStorage and skipped on subsequent logins
   - Native login form POSTs credentials directly to HN (no credential storage in app)
   - Cookies extracted using `@react-native-cookies/cookies` after successful authentication
   - Cookies stored securely in `expo-secure-store` (device keychain/keystore)

2. **Auth Module** (`apps/mobile/lib/hn/`: `errors.ts`, `session.ts`, `web/parsers.ts`, `web/rate-limiter.ts`):
   - **SecureSession** - Wrapper preventing accidental cookie exposure
   - **Error Taxonomy** - Typed errors (NOT_LOGGED_IN, RATE_LIMITED, etc.)
   - **Rate Limiter** - Client-side throttling (30 actions/min)
   - **HTML Parsers** - Extract auth tokens from HN pages with hand-rolled regex parsers (no cheerio); they throw `HNAuthError`

3. **Write API** (`apps/mobile/lib/hn/web/write-api.ts`, also `flag`, `deleteComment`):
   - `login(username, password)` - Authenticate with HN and extract session cookies
   - `vote(itemId, session)` - Upvote stories/comments
   - `unvote(itemId, session)` - Remove upvote
   - `comment(parentId, text, session)` - Post comments
   - `submit({ title, url?, text? }, session)` - Submit a story: GETs `/submit` for `fnid`, POSTs `/r` (`fnop=submit-page`); resolves `{ duplicateOf }` (an item id when HN redirects to the existing item, else null); title max 80 (`HN_TITLE_MAX_LENGTH`)
   - All operations require `SecureSession` with HN cookies (except login)
   - HTTPS enforced, automatic rate limiting, smart error handling

4. **Auth Context** (`apps/mobile/contexts/hn-auth-context.tsx`):
   - Global auth state via React Context
   - Session persistence across app restarts
   - `useHNAuth()` hook provides: `session`, `login()`, `logout()`, `isAuthenticated`

5. **UI Integration**:
   - Login screen: `app/auth/login.tsx` - Native form with direct HN authentication, presented as a sheet
   - Settings screen: Shows login status, login/logout buttons
   - Story cards: Upvote/unvote in context menu (when authenticated)
   - Optimistic updates with automatic rollback on error

6. **Security**:
   - Never log cookies (SecureSession prevents exposure)
   - Session expiration auto-detected → logout + re-login prompt
   - Rate limiting warnings shown to users
   - All requests use HTTPS only

**Note**: Web app remains read-only (no authentication). Write failures on the mobile app go through `presentHNWriteError` (`hooks/present-hn-write-error.ts`) and guards throw `HNAuthError("NOT_LOGGED_IN")`.

The mobile app includes comprehensive user profile viewing for both authenticated users and third-party HN users:

### Search (Mobile)

`app/(tabs)/search/index.tsx` searches Algolia with options from a native header menu (`Stack.Toolbar.Menu`, inline sections, `isOn` checkmarks; the icon fills and tints when anything is non-default):

- **Options** (`SearchOptions` in `lib/hn/read/search-params.ts`): sort (relevance `/search`, newest `/search_by_date`), scope (stories `tags=story`, comments `tags=comment`), date range (`numericFilters=created_at_i>…`) and minimum points (`points>=N`, stories only). Persisted in AsyncStorage (`lib/hn/local/search-options.ts`, via `createJsonListStore`) and read through `hooks/use-search-options.ts`.
- **`author:<name>`** in the query box becomes `tags=…,author_<name>` (`parseSearchQuery`); an author-only query is valid.
- **Pure logic**: `buildSearchParams`, `searchEndpoint`, `parseSearchOptions` (node-tested in `test/hn/search-params.test.ts`). `hnKeys.search(query, options)` includes every param.
- **Comment results** render `SubmissionCommentCard` with `known` story context from the hit (`story_id`, `story_title`), so no per-card lookups; tapping opens the story scrolled to the comment.
- `search_performed` carries sort, scope, date range, min points and `has_author_filter`.

### iCloud Sync (Mobile, iOS)

Free: bookmarks, mutes, blocked users, hidden stories and read state (500 most recent) sync through iCloud key-value storage. Nothing touches our servers.

1. **Native module** `modules/icloud-kv` (local Expo module, autolinked from `modules/`): `ICloudKVModule` with `isAvailable()` (`ubiquityIdentityToken`), `getString`/`setString`/`remove`/`synchronize` and `addExternalChangeListener` (`onExternalChange({ reason, keys })`, reasons `server`, `initialSync`, `quotaViolation`, `accountChange`). Android and web get `unavailable.ts` (no-op, `isAvailable()` false). Config plugin `plugins/with-icloud-kv.js` adds the `com.apple.developer.ubiquity-kvstore-identifier` entitlement; the App ID needs the iCloud capability with Key-value storage in the developer portal.
2. **Engine** `lib/sync/` (pure, node-tested in `test/sync/`): `document.ts` (`{ v: 1, items: { [key]: { value, updatedAt, deleted? } } }`, parse, last-writer-wins merge, tombstone pruning after 30 days, `trimToBudget`) and `engine.ts` (`syncCollection`, the documented algorithm). The local stores do not record deletions, so each collection keeps a base document in AsyncStorage (`@icloud_sync_base_*`, the merged state after the last sync); an item in the base but missing locally becomes a tombstone. Applying a merge patches the local list (never replaces it), so a corrupt or partial remote never wipes local data; corrupt remote JSON is ignored, reported and repaired, a newer `v` is left untouched. The pushed copy is capped (`limit`) and trimmed oldest-first to 150 KB per key; the base keeps the untrimmed merge.
3. **Wiring**: `collections.ts` (adapters over `lib/hn/local/*` `replace*` functions), `run.ts` (serialized run over all collections), `hooks/use-icloud-sync.ts` (mounted in `app/_layout.tsx`: launch, foreground, `subscribeToStoreWrites` from `json-list-store.ts` debounced 2s, `onExternalChange`; invalidates the changed stores' queries and refreshes the Bookmarks widget), `hooks/use-icloud-sync-status.ts` (Settings switch, `@icloud_sync_enabled`, default on when available, `@icloud_last_synced`). Events `icloud_sync_toggled`, `icloud_sync_completed` (once per session). Adding a synced store: add a `replace*` function and an adapter in `collections.ts`.

### Data Fetching Strategy

The app uses a **React Query + HN API** architecture:

1. **API Layer** (`apps/mobile/lib/hn/`):
   - `read/` - Firebase (`firebase.ts`, `getCategoryStoryIds`/`getItem`/`getItems`/`getUser`) and Algolia (`algolia.ts`) fetchers, comment merge and tree helpers, `hnKeys` query keys (use it for every query key, including `hnKeys.allStories()` for invalidation)
   - `web/` - authenticated HTML client (`write-api.ts`), parsers, rate limiter, shared entity decoding
   - `local/` - AsyncStorage persistence (votes, bookmarks, blocked users, hidden items, read stories) built on `createJsonListStore` (`json-list-store.ts`); a write throws when the read failed instead of overwriting stored data with `[]`

   - `local/` - AsyncStorage persistence (votes, bookmarks, blocked users, hidden items, mutes) built on `createJsonListStore` (`json-list-store.ts`); a write throws when the read failed instead of overwriting stored data with `[]`
   - `constants.ts` holds the base URLs (Firebase: `https://hacker-news.firebaseio.com/v0`); `errors.ts`/`session.ts` hold `HNAuthError`/`SecureSession`
   - Import rule: hooks and contexts import from the `@/lib/hn` barrel (types, `STORY_CATEGORIES`/`StoryCategory`, read API, keys, errors, session, write API); `local/*` is imported by deep path; parsers and the rate limiter are internal to `lib/hn`
   - Neighbours of `lib/hn`: `lib/format/` (`time.ts` `timeAgo`, `url.ts` `getDomain`), `lib/html/` (`entities.ts`, `parse.ts` with `stripHTML`/`parseHTMLWithLinks`), `lib/link-preview/og.ts`, `lib/observability/report-error.ts`, `lib/analytics/`, `lib/haptics.ts`, `lib/widgets/`
   - Node tests: `cd apps/mobile && pnpm test` (`test/hn/`, no RN imports allowed in tested modules; see `test/README.md`)
   - `getItem`/`getUser` return `HNItem | null` / `HNUser | null` (Firebase answers `null` for a missing item); callers handle null

2. **React Query Hooks** (`hooks/use-stories.ts`, `hooks/use-story.ts`):
   - `useStories(category)` - Single hook accepting a `StoryCategory` ('top' | 'best' | 'new' | 'ask' | 'show' | 'jobs', from `@/lib/hn`)
     - Uses `useInfiniteQuery` with dynamic query key `['stories', category]`
     - Maps category to appropriate API fetcher (`getCategoryStoryIds`)
     - Only one query active at a time - switching categories reuses cached data instantly
   - `useStory(id)`, `useComment(id)` - Use `useQuery` for individual items
   - Global QueryClient configured in `app/_layout.tsx` with:
     - 2 minute staleTime
     - 10 minute gcTime (24h for `stories`/`story`, see Offline cache)
     - 2 retries
     - refetchOnWindowFocus enabled

3. **Infinite Scrolling Pattern**:
   - `useStories(category)` uses `useInfiniteQuery` with `pageParam` tracking offset
   - Page size: 30 items
   - `getNextPageParam` returns next offset or undefined when done
   - Stories are flattened from pages in components: `data?.pages.flatMap(page => page)`
   - Automatic caching by React Query - switching between categories is instant after first load

4. **Smart Prefetching Strategy** (`hooks/use-app-prefetch.ts`):
   - **Global prefetch on app open** - All 6 categories prefetched automatically
   - Triggered from `app/_layout.tsx` when app mounts (not tied to specific screen)
   - Waits 1.5s after mount to allow initial category (Top) to load first
   - Warms the first page of every category in parallel via `prefetchCategory` (from `hooks/use-stories.ts`)
   - **Result: Instant category switching** - no loading spinners after prefetch
   - Skips OG metadata prefetch for background categories (bandwidth optimization)
   - `prefetchCategory` no-ops for any category already cached (deduplication)
   - This is the single source of background warming - the feed screen no longer runs its own predictive/idle prefetch

5. **Offline cache** (`lib/query-cache/`, `app/_layout.tsx`):
   - `PersistQueryClientProvider` saves the React Query cache to AsyncStorage (`persister.ts`: 2s throttle, `maxAge` 24h, `buster` = app version + `PERSIST_SCHEMA_VERSION`). Launch shows the saved data while the refetch runs.
   - `persist-policy.ts` (pure, tested) decides what is saved: successful feed lists (first 2 pages each, via `serializeData`) and `story` threads of bookmarks plus the 20 most recently fetched. Local stores, auth, search, items, OG and users are never saved. A payload over 4MB is not written (reported once via `reportError`).
   - Saved queries get a 24h `gcTime` (`keepPersistedQueriesAlive`); the default 10 min would evict them and their disk copy.
   - `online-manager.ts` feeds `expo-network` state into React Query's `onlineManager` (queries pause offline, refetch on reconnect). `useIsOffline()` drives `OfflineBanner` (feed and story detail, only over cached data, `offline_banner_shown` once per session). Offline with nothing saved the screens show "You're offline" via `ErrorState` (`fetchStatus === "paused"`).
   - Bookmarking prefetches the thread (`prefetchStoryThread`); the Bookmarks tab runs `useOfflineBookmarks` once per mount (missing threads only, max 50, 4 at a time). Settings → Clear Cache also calls `queryPersister.removeClient()`.

## Important Implementation Notes

1. **Infinite Query Data Structure**: The `useStories(category)` hook returns paginated data. Always flatten with `data?.pages.flatMap(page => page)` before rendering.

2. **HN API Behavior**: The API returns story IDs first, then requires individual item fetches. The `getItems()` helper parallelizes these fetches.

3. **Comment Loading**: Comments are lazy-loaded individually. Deleted/dead comments are filtered out by returning null in the component.

4. **Time Display**: `timeAgo` (`lib/format/time.ts`) formats timestamps (e.g., "2h ago", "3d ago").

5. **URL Extraction**: `getDomain` (`lib/format/url.ts`) parses the URL and strips a leading `www.`; the app and the widget sync share it.

6. **Platform Differences**: Android requires extra bottom padding (100 + safe area) due to tab bar rendering differences.

7. **Theme Colors**: Read colors from `useTheme().colors` (tokens in `constants/colors.ts`), never hardcoded hex.
